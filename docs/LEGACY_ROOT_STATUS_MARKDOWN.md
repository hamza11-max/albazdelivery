# Legacy root-level status documents

The repository contains multiple root-level files whose names suggest **completion** (`FINAL_*`, `COMPLETE_*`). **They are not authoritative** for shipping decisions.

**Use instead:**

- **[TECHNICAL_PROJECT_AUDIT.md](TECHNICAL_PROJECT_AUDIT.md)** — evidence-based phases A/B/C and honest gaps.
- **[CHANGELOG.md](../CHANGELOG.md)** — dated summary of remediation work.
- **[ARCHITECTURE_SNAPSHOT.md](ARCHITECTURE_SNAPSHOT.md)** — short architectural orientation.

Historical files were left in-tree to avoid breaking bookmarks; treat them as **session notes / marketing drafts**, not release certification.

---

### Indexed filenames (may drift)

**`FINAL_*`** (examples): `FINAL_STATUS.md`, `FINAL_BUILD_STATUS.md`, `FINAL_BUILD_FIX.md`, `FINAL_COMPLETION_SUMMARY.md`, `FINAL_COMPLETION_REPORT.md`, `FINAL_VERIFICATION.md`, `FINAL_IMPLEMENTATION_SUMMARY.md`, `apps/customer/FINAL_IMPLEMENTATION_SUMMARY.md`, `app/customer/FINAL_IMPLEMENTATION_SUMMARY.md`.

**`COMPLETE_*`** (examples): `COMPLETE_PROJECT_STATUS.md`, `COMPLETE_SESSION_SUMMARY.md`, `COMPLETE_IMPLEMENTATION_SUMMARY.md`, `COMPLETE_FEATURE_LIST.md` (+ parallel paths under `app/customer/` and `apps/customer/`).
